# Clinical summary factuality protocol

This document describes the reusable source-grounded annotation and generation protocol. Current execution status is in [the framework report](factuality_report.md); the separate [free-model pilot](openrouter_factuality_pilot.md) records its actual API calls and development results.


Research question: which factual failures does ROUGE miss, and where does the selected BioBART-large + LoRA summarizer contradict, invent, or omit source information? This is an exploratory validation study: validation already influenced model selection. The test split stays untouched by this harness. Synthetic cases are diagnostics and never enter real-case denominators.

## Sampling and generation

Default: group validation CSV by string `ID` in pandas' default sorted order, concatenate dialogue rows with one space, then `sample(n=min(100, N), random_state=42)` exactly as `eval_notebook_protocol.preprocess_data`. Record original row indices, dialogue IDs, split, CSV SHA256 and dialogue SHA256. The source CSV is fixed by submodule commit plus file hash. Repeated dialogue rows are preserved, not deduplicated. Full reference text is retained, not treated as exhaustive truth.

Primary protocol is `flask-note`: existing `/generate_note` via Flask test client, 512 input tokens with max-length padding, deterministic 4-beam decoding, repetition penalty 2.0, no-repeat 4-grams, output max_length 512. The model stays on the device chosen by the unmodified application (currently CPU). Capture token IDs, attention mask, decoded non-padding model input and full token count using the actual tokenizer. These IDs are authoritative; decoded byte-level BPE fragments may not be faithful character spans of original dialogue. Reviewer visibility spans therefore refer to decoded model input separately from original dialogue. Unknown visibility is unclear, never presumed visible. Route strips surrounding whitespace; export records the actual request dialogue.

Notebook scores use output max_length 128, target truncation 256 and a different section mapping. Notebook and Flask scores cannot be combined. Audit: duplicate `EXAM` in training/notebook maps to `exam`, Flask maps to `physical exam`; `EDCOURSE` is called `educational courses`, `FAM/SOCHX` is called `social history`; unknown headers yield empty notebook section but Flask falls back to HPI. Each grouped target uses its first header for every reference row. Record all original headers. Do not fix these behaviors during evaluation.

Historical cached predictions contain references/predictions but no IDs, source hashes, model revisions or exact input IDs. Even unique reference matches do not prove generation provenance. Audit them as unscorable; do not relabel them as current-model results. Newly generated outputs have their own manifest. The local generation and annotation stages make no external judge calls. The separately documented semantic pilot uses a free API reviewer.

## Annotation and rubric freeze

Use original dialogue as evidence. Speaker roles matter: another person's condition is not the patient's; clinician questions are not established findings. Preserve negation, uncertainty, temporality, doses, units and attribution. Paraphrases can be supported without lexical identity. A reference helps section coverage; validate every expected fact against source. Do not infer sex or gender from a name, pregnancy, relationships, or ambiguous pronouns. Distinguish explicit sex descriptions, gender identity, and pronoun references; do not collapse these dimensions. Conflicting or ambiguous source is `unclear`.

Two-pass review: use `plan` to export a source-only JSONL queue (no prediction). Review source and requested section; enter atomic, clinically relevant expected facts with original source spans. Mark relevance `expected` or `excluded`, explaining exclusions. Freeze this plan before viewing the corresponding prediction, setting `expected_facts_frozen=true`, `expected_facts_reviewer`, `expected_facts_reviewer_kind`, and `expected_facts_frozen_at` in the annotation record. After a small source/prediction pilot (suggested 5 cases), record actual pilot counts, disagreements, rubric changes and a human freeze date in the run record. Apply the frozen rubric to the remainder. This implementation's v1 is an engineering rubric, **not a completed human pilot**. No human pilot/freeze/review is claimed. Omission rates remain N/A until the expected-fact pass is actually completed. Existing generated outputs can be reviewed through the blind plan queue, but reviewers who already saw an output must disclose that and exclude its omission plan from unbiased rates.

Atomize output into distinct propositions. A sentence may contain several claims. Each claim has one label: `supported`, `contradicted`, `unsupported`, `unclear`, or `pending`. Fact type is separate: `age`, `sex`, `gender`, `pronoun`, `medication`, `diagnosis`, `symptom`, `quantity`, `date`, `other`. An age contradiction is one contradicted claim tagged age, not an additional unsupported claim. Incorrect explicit identity references require matching the same source dimension. Missing demographics are omissions only when predeclared relevant expected facts.

Expected facts receive `present`, `omitted`, `unclear`, `pending`, or `excluded`. Excluded details do not enter omission denominators. Record source spans (0-based, end-exclusive Unicode character offsets into `dialogue`) and generated spans (into `prediction`); visible evidence spans index `model_input.text`. Include exact text at each span and a rationale. `unsupported` requires a rationale documenting a full-source search and empty source evidence if none exists. A contradiction needs positive source evidence. Every final label has `visibility`: `visible`, `truncated`, `unclear`; visible supported/contradicted claims and expected facts need model-visible evidence spans. Unsupported claims are visible-assessable only after a full-visible-input search, with explicit rationale; absence is not provable by one span. Claims supported by full source but beyond the input are not hallucinations; missing beyond-input expected facts contribute to truncation coverage loss, not model-visible omissions.

Annotation identity includes `reviewer` and `reviewer_kind` (`human`, `agent`, `model`, `synthetic`), status `pending`, `partial`, or `complete`, claim and expected-fact completeness booleans, unresolved items, and case/prediction hashes. Preserve real reviewer identity; never populate a human name automatically. Automatic demographic checks only **suggest** labels and cannot complete annotations. No human reviewed labels currently exist unless supplied later. Agent inspection can illustrate findings but is not human gold or population error-rate evidence.

## Metrics and denominators

Score each reviewer kind separately. Human results are primary; agent/model/synthetic outputs are distinct strata. Validate all spans, IDs, hashes and status before aggregation. Pending and unclear labels never pass. Empty complete claim annotations for a nonempty prediction are invalid; empty expected-fact sets can be complete if the frozen source-only review explicitly found no relevant expected facts.

For both full-source and model-visible views report:

- Age contradictions: contradicted age claims / assessable age claims (supported + contradicted + unsupported); unsupported age claims stay in the denominator but are also counted once under unsupported claims.
- Sex/gender-reference contradictions: contradicted sex, gender or pronoun claims / assessable claims of these types, also broken out by type.
- Unsupported claims: unsupported / all assessable atomic generated claims. Contradictions are reported separately, not double-counted.
- Expected-fact omissions: omitted / (present + omitted) expected facts in frozen, unbiased source-only plans. Excluded/pending/unclear facts stay outside the eligible denominator.
- Summaries with an assessable error: cases with at least one contradicted/unsupported claim or relevant omission / cases with at least one assessable item. This is an **assessed subset** rate, not full-sample accuracy. Also report fully reviewed summaries, partial cases, and pending/unassessable cases separately. No-error passing summaries require complete claims AND expected-fact review, no pending/unclear/unresolved items.

Use null (render as N/A) when a denominator is zero. Report case and item review coverage, unclear/pending counts, automatic flagged case counts, truncation case counts, and expected facts/omissions unavailable through truncation. Do not estimate checker precision/recall from pending real labels. Synthetic diagnostics have known labels, remain separate, and are not clinical validation. No inter-rater agreement without independent real reviews.

ROUGE remains a separate overlap measure, using stemming and identical paired source cases only. Historical notebook ROUGE is linked for context, not joined to this run. ROUGE does not measure clinical safety. Do not attribute BART-base versus BioBART-large differences solely to biomedical pretraining because model size differs. Baseline comparisons are optional and require identical cases, protocol and paired review; this pass prioritizes the selected model and annotation readiness.

## Data handling and limitations

MTS-Dialog by Ben Abacha et al. (EACL 2023), https://github.com/abachaa/MTS-Dialog, is provided under CC BY 4.0 in `MTS-Dialog/LICENSE.txt`. Keep that attribution and license with derived excerpts. Dialogue text in this artifact is concatenated/trimmed; predictions and annotations are derived additions. Raw export and review files stay in ignored `results/factuality/local/`; commit only hashes, aggregate artifacts, synthetic fixtures and attributed minimal inspected excerpts. No patient-care recommendations follow from this study. Human review, ambiguous evidence, section relevance, model-visible truncation, and selection bias constrain interpretation.

See the [v2 report](factuality_report.md) for the separately saved rerun, regression scope and remaining limits. Unclear review candidates are distinct from contradictions, full-source and model-visible evidence are compared separately, and all automatic outputs remain pending outside annotated error rates. Earlier automatic snapshots retain their original checker behavior.

## Evaluator qualification and blinded semantic review

Use the [published-methods redesign](factuality_report.md) and [research rationale](frontier_eval_research.md) for capability measurement and semantic-judge calibration. Keep known-example regressions separate from new capability tests and independent clinical holdouts. The demographic checker is an unvalidated screen, not the primary clinical judge. Blinded visible-only judgments must freeze before full-source/planning exposure; model tasks require isolated contexts. Fixed-property classification does not establish exhaustive claim extraction. Expected-fact omissions require an independently frozen source inventory; review coverage and completed pilot work are reported separately in the current framework report.
