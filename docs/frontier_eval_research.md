# Published frontier evaluation methods and this implementation

Research date: October 17, 2026 (America/New_York). Scope: published lab methodology and primary research, not access to private evaluation infrastructure. The recommendation is to combine independent clinical judgments, source-grounded atomic-claim checks, and separate capability/regression tests. A larger regex test suite cannot substitute for those components.

## What the sources actually do

| Primary source | Method worth adapting | Adaptation here and limits |
|---|---|---|
| [OpenAI: evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) | Task-specific datasets; automated scoring calibrated against people; classification/pairwise judgments; continuous evaluation; attention to position and verbosity bias. | Judge tasks ask explicit claim labels with evidence, omit author model names and prior grades, and separate pending reviews. Existing discovered failures remain regression data. A new synthetic capability suite is separate. This is a methodology adaptation, not an OpenAI product integration. |
| [OpenAI: HealthBench](https://openai.com/index/healthbench/) | Conversation-specific physician-written criteria; model grades per criterion; meta-evaluation compares grader judgments against physician judgments and physician-to-physician agreement. | The source-only planning and independent review stage must precede factual omissions. Fixed factual properties can be graded individually; full-summary inventories look for additional claims. Expert criteria, importance weights and calibration require actual clinicians and remain pending. Our authored rubric is not physician-validated. HealthBench measures health assistance, so its score is not transferable to transcript summarization. |
| [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | Distinguish capability evaluation from regression protection; combine deterministic, model and human graders; test both desired behavior and false triggering; inspect transcripts and repeat trials. | Freeze the current deterministic screen; run a new challenge that can fail; report false alarms and non-extraction; preserve judge identity/configuration per trial and queue disagreements. A consensus proposal needs agreement across declared judge families. Multi-turn agent pass@k is not used as a substitute for factuality of one saved summary. |
| [Google: FACTS Grounding paper](https://arxiv.org/html/2501.03200v1) | Evaluate judge prompts against labeled human examples, using macro F1 and false-positive/negative metrics; combine different judge models; separately check whether responses meaningfully answer the request. | `meta.py` measures the evaluator itself. `judging.py` retains independent judge/trial results and disagreement rather than manufacturing gold from a majority vote. Claim completeness and requested-section coverage are separate from whether extracted claims are supported. Empty or incomplete output cannot become a fully reviewed factuality pass. We use conservative unanimity for proposals; this is not FACTS' exact aggregation or official score. |
| [Google: FACTS Benchmark Suite, December 2025](https://deepmind.google/blog/facts-benchmark-suite-systematically-evaluating-the-factuality-of-large-language-models/) | Different factuality settings need distinct evaluations; public development data and private held-out evaluation are separate. | Grounding to the patient's dialogue is the task here. Parametric trivia or a model's medical knowledge cannot establish a patient's age or medication. Existing validation dialogues and inspected claims are development data. The MTS-Dialog test split remains untouched; an independently curated clinical holdout is still required. |
| [FActScore, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.741/) | Decompose long output into atomic facts and measure support against a reliable source rather than assigning a single holistic factuality impression. | Fixed property tasks include the target span and prediction context. Whole-summary inventories cover claims beyond the already discovered demographics. Extraction coverage and ungraded items are explicit; excluding missed claims would inflate the grader's apparent quality. Patient transcript grounding replaces biography/Wikipedia evidence. We do not report an official FActScore or import its measured accuracy. |
| [FENICE, 2024](https://arxiv.org/html/2403.02270v2) | Extract atomic claims, then compare them against source sentences or broader source blocks using entailment/contradiction reasoning. | The file protocol requires decisive source spans for support and contradiction and distinguishes unsupported from contradicted. Wider speaker context is available to prevent relative/provider attribution errors. We did not install or run FENICE's trained NLI components; a model-based semantic grader remains an explicitly pending execution stage. |
| [Google: SAFE / LongFact](https://deepmind.google/research/publications/85420/) and [official implementation](https://github.com/google-deepmind/long-form-factuality) | Break output into facts and verify with evidence; evaluate the fact-checker against annotated data; retain the evaluation pipeline. | Adapt the evidence-verification pattern. Do not use web search to invent patient-specific facts or preferred identities. The supplied full/visible dialogue is the evidence corpus. No SAFE performance number or claim of human-level grading transfers to this evaluator. |
| [When Rubrics Fail, September 2026 preprint](https://arxiv.org/html/2609.12718v1) | Test whether a medical evaluator notices a single injected error in a matched otherwise unchanged response; programmatically verify edits; independently check error validity. The paper also reports that fixed rubrics can miss added claims. | Controlled edits and paired scoring complement the fixed rubric. The correct/corrupted members share a source; the declared edit reconstructs the mutation exactly. This suite's construction labels are synthetic, not clinician-validated. The preprint motivates stress testing; its conclusions and measured performance are not assumed to generalize. |

## The design chosen for this repository

There were three practical options. Extending the demographic rules again would improve a narrow screen while leaving general clinical claims unmeasured. Replacing everything with one LLM judge would handle more wording but introduce an uncalibrated source of errors. The chosen design combines a narrow frozen screen, a falsifiable capability suite, and a calibrated semantic-review workflow with expert adjudication.

The primary factuality endpoint should come from exhaustive atomic claims assessed against source evidence. Contradiction, unsupported addition and relevant omission remain separate. Omission recall requires an independent source-only inventory frozen before the output is shown. Patient sex, gender identity, pronouns and honorifics are separate evidence dimensions. Clinical importance cannot be supplied by arbitrary programmer weights.

For grader calibration, compare candidate judge configurations on the same labeled cases, inspect false positives and false negatives, then select the configuration on development/calibration data. Evaluate the frozen configuration once on a different clinically labeled holdout grouped by original dialogue. Keep every model's versions of one dialogue in the same split. Once test examples are inspected to fix the grader, they become development data and a new holdout is needed. Hashing known examples does not make them independent.

A provisional clinical review study should include at least two qualified independent reviewers, adjudication of disagreements, a random representative sample alongside deliberately enriched rare-error cases, and recorded sampling probabilities. Report the enriched set's sensitivity separately from population prevalence. A case-level or dialogue-cluster bootstrap is appropriate for correlated claims and paired model comparisons. Report sensitivity, false-positive rate, uncertainty and abstention coverage; a small count of zero false alarms does not establish zero risk. Study size and clinical acceptance criteria require an expert decision before unblinding, not thresholds reverse-engineered from favorable results.

For stochastic semantic judges, retain all trials instead of selecting the most flattering response. At least two declared judge families are needed for a consensus proposal; agreement alone is not correctness, and model families need not be statistically independent. Human adjudication of disagreement and sampled agreement cases is still necessary. Never use the summarizer's own uncalibrated verdict as the gold label.

## Concrete implementation

- `factuality/challenge.py`: versioned controlled edits, exact-duplicate removal, typed target spans, synthetic gold, freeze manifest and baseline hash checks.
- `factuality/meta.py`: full confusion matrices, macro F1, per-class precision/recall, error sensitivity, false alarms, coverage, matched pairs and family-clustered intervals. Unextracted/ungraded claims stay in denominators.
- `factuality/judging.py` and `factuality/prompts/claim_judge_v1.txt`: blinded provider-neutral tasks, exact evidence validation, per-trial provenance, strict result imports, consensus proposals and disagreement queues.
- Blinded full-summary inventory tasks for all 300 saved outputs, in both full-source and model-visible views. Source-only expected-fact planning packets are separate; their reviewers must not open outputs first.

This work intentionally has no paid API or hosted-platform dependency. Judge-facing JSONL can be processed by an authorized local or hosted model and imported through `judge-score`; actual model, revision, family, settings and trial must be retained. Providing prompts and an importer is not the same as executing or calibrating a semantic judge.

## Current scope

The current implementation and results are described in [the framework report](factuality_report.md) and [the free-model pilot](openrouter_factuality_pilot.md). Local demographic screening was executed on 300 saved summaries; semantic review was executed on the constructed development subset. Clinician calibration, complete claim/omission annotation on real summaries and an independent clinical holdout were not performed. The project adapts the published design principles above without claiming to reproduce private frontier-lab infrastructure or clinical accuracy.
